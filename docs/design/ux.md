# UI and user experience

## Tone: a quiet tool

Opened for ten minutes, not played for a streak. Looks like an editor, behaves like a
drill, reports like an instrument. Decisions taken 2026-10-11:

| decision | choice | why |
|---|---|---|
| pages | practice, stats, settings; nothing else | the loop is the product |
| during an exercise | task, editor, mode indicator only; no par, no live count | solve, don't reverse-engineer |
| timing | invisible; reported after each exercise | keybr-style calm; no arcade pressure |
| theme | dark only, colourblind-safe target highlights | audience, time |
| mobile | unsupported, say so plainly | modal editing needs a keyboard |
| replay | static par shown after; no animated replay yet | cheap first, learn-value later |
| gamification | none; no streaks, badges or leaderboards | learners who already use Vim want data, not Duolingo |
| input | keyboard only; mouse never required | reaching for the mouse is a design failure |
| feedback | hints after the exercise, never blocking mid-exercise | hardtime.nvim's blocking is resented |

## The practice screen

One screen, four regions, no chrome. Text wireframe (desktop, ~100 columns):

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│ vim-trainer      python · neovim      focus: ci"  strings           [s]tats [,]  │  ← header, 1 line
├──────────────────────────────────────────────────────────────────────────────────┤
│ Change the string passed to logger.warn to  retrying                              │  ← task, 1 line
├──────────────────────────────────────────────────────────────────────────────────┤
│  1  def fetch(url, attempts=3):                                                   │
│  2      for i in range(attempts):                                                 │
│  3          try:                                                                  │
│  4              return get(url)                                                   │
│  5          except Timeout:                                                       │
│  6              logger.warn(▌"timeout, trying again"▐)   ← target highlighted     │
│  7              sleep(2 ** i)                                                     │
│  8      raise GiveUp(url)                                                         │
│                                                                                   │
│ NORMAL                                                                            │  ← mode line
├──────────────────────────────────────────────────────────────────────────────────┤
│ ci"  ·  confidence 0.71  ·  12 reps  ·  trend ↑            [?] hint  [Esc Esc] skip│  ← footer
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **Header**: language and editor profile (click or `,` to change), the current focus
  skill in plain words, link to stats. Nothing else.
- **Task**: one sentence, generated by the template. Literal text to type is set off
  visually so it is unambiguous.
- **Editor**: CodeMirror 6 with `@replit/codemirror-vim`. Relative line numbers on by
  default (toggle in settings). The target node gets a background highlight that is
  distinguishable by shape as well as colour (underline + tint). Cursor is a block in
  normal mode, a bar in insert, matching real Vim. The mode line is large and always
  visible, because losing track of the mode is a common source of errors.
- **Footer**: the skill being drilled with its confidence and sample count. `?` reveals
  one hint (costs nothing, but is logged). `Esc Esc` skips (logged as a miss).

Nothing shows the par, a timer, or a keystroke counter while solving.

### After each exercise: the result strip

Replaces the footer for as long as the user wants; any key continues.

```
├──────────────────────────────────────────────────────────────────────────────────┤
│ ✓ correct   you: f"ci"retrying<Esc>  (16 keys, 4.2 s)   par: ci"retrying<Esc>  (12) │
│ hint: ci" works from anywhere inside the quotes, so the f" was unnecessary.         │
│                                                              [space] next  [r]etry │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- Pass/fail, your keystrokes (normalised, `<Esc>` style), count and time, the par
  keystrokes and count.
- One hint sentence, chosen from the exercise's `hints` by what the user did (e.g.
  used `f"` before `ci"`, pressed `j` seven times, used `x` repeatedly).
- `space` for next, `r` to retry the same exercise (retry does not count toward
  confidence). If the result was a fail, the expected buffer is shown as a diff.
- Not built: an animated replay that plays the par keystroke by keystroke in the editor.

The strip is where learning happens. It must appear instantly (no network) and be
readable in under two seconds.

### Keyboard flow, end to end

```
land → [enter] start → exercise → solve → result strip → [space] → exercise → ...
                                        ↳ [r] retry            ↳ [s] stats  ↳ [,] settings
```

No modal dialogs. Settings and stats are full-screen views reached and left with a
key (`,` and `s` from the result strip or header; `Esc` returns). While the editor has
focus, every key goes to Vim; the trainer's own shortcuts are only live on the result
strip and header. This avoids stealing keys like `s` or `,` from Vim.

## First visit

No account, no email. Three questions and a test, under six minutes:

1. **Language** — pick one (Python, C++, TypeScript, ...). Changeable any time.
2. **Editor** — Neovim / Vim, VS Code + VSCodeVim, JetBrains + IdeaVim. Sets the
   track and hides unsupported commands.
3. **Relative line numbers?** — yes (default) / no. Affects `m.rel` drills.
4. **Placement test** — twelve exercises, five minutes, in the chosen language. Framed
   as "let's see where you are", not as a test. No pass/fail; it seeds the chart.
   Placement is per language; the first switch to a new language opens its placement
   (skills mastered in another language are skipped; `x` skips the whole placement).

Then the first stats screen (below), with the focus skill named and a single line:
"We'll start with `ci"`. Press enter." That chart, showing a few skills strong and
several weak, is the moment the trainer's point becomes clear. Everything stays in
`localStorage`; there are no accounts (ADR 0012).

### Onboarding copy rules

- No skill ids (`m.rel`, `o.ciquote`) on any screen before the first exercise. Name
  the thing in words or show the keys (`ci"`); ids belong on the stats screen.
- One instruction per screen; the key to continue is always shown.
- The placement framing stays "let's see where you are", never "test" or "score".

### Placement complete

When the last sample lands, the stats screen opens with one line on top:
"placement complete: N skills placed, M mastered." (or "placement skipped."), and the
focus skill is computed once there, so `Enter` drills exactly the skill it names.
Without that line, placement ended by dropping straight into the chart, which QA testers
read as an error (qa-findings.md, #36).

## Routes, Back and reload

The URL hash is the single source of truth for which screen is showing: `#practice`,
`#stats`, `#settings`, `#placement` and `#placement-intro` (`ROUTES` in `main.ts`; an
empty or unknown hash means practice). Keys and links the player uses (`s`, `,`, the
header links) push a history entry; internal hops replace the current one. The app
renders from the hash on load and on `hashchange`, and the renderer applies the guards,
so every hash is safe to load directly. Consequences:

- Browser Back returns to the previous screen, not out of the site. `Esc` goes back
  when the app pushed the current entry, else to practice; after a language change it
  always goes to practice.
- Reload shows the same screen. Mid-placement it resumes at the next unanswered
  sample (adaptive-model.md); mid-practice it starts a new session.
- On a first visit every hash except `#settings` shows the setup questions (settings
  stays open so a save can be imported). `#practice` or `#placement` for a language
  that has not been placed goes to `#placement-intro`, and `#placement-intro` for a
  placed language goes to practice, so a skipped placement is not re-entered.

## The stats screen

Instrument, not dashboard. Two views, toggled with `tab`:

**Skills** — the skill graph as a grid grouped by tier. Each cell: skill keys, a
confidence bar, sample count, trend arrow. Locked skills are dim. The focus skill is
outlined. `enter` on a cell shows that skill's history chart and lets the user force
it as the next focus ("drill this").

**Progress** — one line chart per selected skill (default: focus skill and the three
weakest), time-to-solve and keys/par over sessions, with keybr's projection line and
its caption ("`t.paren` at target in ~6 sessions"). A sessions table below: date,
minutes, exercises, skills improved.

Charts follow the dataviz skill's rules: brand-neutral palette, readable in dark mode,
every series labelled inline (no legend hunting), tooltips on hover but values also
visible without hover for keyboard users.

## Session end

There is no forced session length. Closing the tab is fine; state is saved after every
exercise. If the user presses `q` on the result strip, a one-screen summary appears:
minutes, exercises, skills improved, one unlock if any, and one line "try in your
editor today: `"_d` deletes without clobbering your yank." That line is the bridge
from drills to real work and is generated from the session's most-improved skill.

## Settings (`,`)

Language; editor profile; relative numbers; `jk`/`Ctrl-[` escape preference (affects
par counting for `<Esc>`); keyboard layout note (par counts are layout-independent);
theme (dark only, placeholder); data export (JSON) and import; reset.

## Accessibility and comfort

- Target highlight uses tint + underline; never colour alone. Check with a deuteranopia
  simulator whenever the palette changes.
- All text ≥ 14 px; editor font configurable, default a system monospace.
- No animation. No layout shift when the result strip appears (reserve its height).
- Works offline once loaded (static assets, localStorage). There is no service worker
  yet, so a reload needs the network.
- Screen-reader support is out of scope; the trainer is visual-spatial by nature, and
  the docs say so.

## Explicitly not built

Accounts, sync, leaderboards, streaks, social sharing, custom exercise authoring,
animated replay, light theme, mobile layout, an in-page tutorial (link to `:Tutor`).
